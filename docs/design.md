# Design: In Situ ML Phase Detection in GPU-Accelerated Parallel MD

CSCI 596 final project (Fall 2026), solo. Programming project.

## 1. Story (Problem / Finding / So what)

**Problem.** Crystal nucleation in a supercooled liquid happens in a short, random window inside a long
simulation. Catching it post hoc means writing the full trajectory to disk at high frequency, and I/O,
not compute, becomes the bottleneck at scale.

**Finding (target).** A GPU-accelerated spatial-decomposition MD code with a dedicated group of in situ
analysis ranks classifies every atom as liquid or crystal on the fly, using Steinhardt bond-order
features and a small neural network, and tracks the largest crystalline nucleus over time while writing
only labels, not trajectories.

**So what.** The same simulation/analysis communicator split works for any large simulation where
storing everything is too expensive. We report the cost of analysis (percent of step time) against the
I/O it avoids (bytes not written).

## 2. Physical model

- Lennard-Jones atoms, reduced units (σ = ε = m = 1), cutoff r_c = 2.5.
- Velocity Verlet, Δt = 0.005, periodic boundaries, linked-list cells (as in the course `pmd.c`).
- NVT via a velocity-rescaling (Berendsen-style) thermostat, applied globally with `MPI_Allreduce`
  on kinetic energy.
- Protocol: FCC lattice → melt at T* = 2.0 → quench to T* ≈ 0.55 at ρ* ≈ 0.95 → hold and watch.
  The exact (ρ*, T*) quench point is tuned in a Phase 1 smoke test so nucleation is likely within the
  run budget.
- **Primary run is seeded:** a small spherical FCC seed (fixed lattice positions for the first ~1k steps,
  then released) placed in the supercooled liquid. Growth is deterministic enough to always produce a
  result. Unseeded homogeneous nucleation is a bonus run if compute time allows.

## 3. Parallel architecture

```
MPI_COMM_WORLD (P ranks)
  └─ MPI_Comm_split(color = rank < P_sim ? SIM : ANA)
       SIM comm  (P_sim ranks, 1 GPU each): spatial decomposition MD
       ANA comm  (P_ana ranks, CPU):        in situ analysis
  Each ANA rank serves a fixed group of P_sim / P_ana SIM ranks.
```

### 3.1 Simulation ranks
- Base: course `pmd.c` (spatial decomposition, atom caching from 6 neighbors, atom migration).
- Halo exchange and migration stay on the host, unchanged.
- Force computation moves to CUDA: each step, copy positions of resident + cached atoms H→D, build a
  cell list on the GPU, compute LJ forces and potential energy for resident atoms, copy forces D→H.
  This keeps MPI logic identical to the CPU code, which makes CPU/GPU validation direct.
  (Device-resident positions with halo-only transfers are an optimization, only if time allows.)
- A compile-time switch (`-DUSE_CUDA`) keeps the CPU force path for comparison.

### 3.2 In situ analysis ranks
Every K steps (K = 100 by default):
1. Each SIM rank sends its resident atoms **plus its cached boundary atoms** (flagged) to its ANA rank
   with non-blocking sends, so SIM ranks keep stepping while analysis runs.
2. ANA rank computes, for each resident atom, neighbors within r_q = 1.5 (first minimum of g(r)),
   then q_lm for l = 4, 6, then Lechner–Dellago averaged q̄4, q̄6. The cached atoms supply the
   neighbor shell needed for averaging at subdomain edges.
3. Features [q̄4, q̄6, q4, q6, coordination number] → MLP → liquid / crystal label.
4. Crystalline atoms (positions + labels only) are gathered to ANA root, which finds connected
   clusters (neighbor distance < r_q) and records the largest-nucleus size n_max(t).
5. Output per analysis step: n_max, crystalline fraction, and a compact label file for visualization.
   Full XYZ snapshots are written only every M analysis steps for the movie.

### 3.3 Classifier
- Training data generated by our own code: snapshots of thermalized perfect FCC (label 1) and
  equilibrated liquid (label 0) at the quench temperature, features computed by the same C code that
  runs in situ. No external dataset.
- PyTorch MLP: 5 → 16 → 16 → 2, ReLU. Trained offline.
- Weights exported to a C header (`mlp_weights.h`); inference is a hand-written C forward pass in the
  ANA ranks. No Python inside the MPI job.
- Baseline to beat: threshold on q̄6 alone. Report both accuracies, especially near the interface.

### 3.4 Compute (CARC Discovery, account `anakano_429`)
- `gpu` partition: A100 (2/node, 20 nodes), A40, V100, L40S. `debug` partition: A40 for smoke tests.
- Toolchain: `cuda/12.6.3`, `openmpi/5.0.5`.
- Starting code: Assignment 4 `pmd.c` (Part 1) and `pmd_split.c` (Part 2, which already splits
  `MPI_COMM_WORLD` into MD workers and an analysis group).

## 4. Validation

| Check | Pass criterion |
|---|---|
| GPU vs CPU forces | Max relative error < 1e-10 (double precision) on the same configuration |
| NVE energy conservation (thermostat off) | Total energy drift < 1e-4 per atom over 10k steps |
| g(r) of liquid | Peak positions match standard LJ liquid g(r) |
| Thermostat | T(t) settles at target within 1% |
| Classifier | > 95% held-out accuracy; beats q̄6 threshold |
| In situ vs post hoc | In situ labels identical to post hoc labels computed from a full dump of the same run |

## 5. Measurements (results section)

1. **GPU speedup:** step time, CPU force path vs CUDA force path, per rank, vs N.
2. **Strong scaling:** fixed N, P_sim = 1, 2, 4, 8 GPUs (subject to CARC availability).
3. **Weak scaling:** fixed N / P_sim.
4. **In situ overhead:** SIM step time with analysis on vs off; as a function of K and P_ana.
5. **I/O savings:** bytes written in situ vs a full XYZ dump at the same frequency.
6. **Science:** n_max(t) curve and crystalline fraction over time; OVITO video with atoms colored by label.

## 7. Risks

| Risk | Mitigation |
|---|---|
| No homogeneous nucleation in the run budget | Seeded run is the primary result |
| Limited GPU allocation on CARC | Strong scaling to as many GPUs as available; RunPod as backup for single-node runs |
| Analysis ranks slower than K steps of MD | Increase K, add ANA ranks; report the trade-off as a result |
| Classifier poor at the interface | Neighbor-averaged features; report q̄6-threshold baseline honestly |
